## Bugs Fixed in This Session

### 1. KXMLGUI RC File Not Found in Dev Builds

**Symptom:** App launched with empty menus and no toolbar — no way to
connect or sync except via Dashboard buttons.

**Root Cause:** `setupGUI(Default, "qpilotsyncui.rc")` searches KDE standard
paths (`~/.local/share/kxmlgui6/qpilotsync/`), but development builds don't
install the file there.

**Fix:** Added `QPILOTSYNC_DATA_DIR` compile definition pointing to the
source tree's `data/` directory. In dev builds, `setupGUI()` receives the
absolute path directly. Installed builds fall back to the standard KDE path
lookup.

**Files:** `src/CMakeLists.txt`, `src/kf6/kf6mainwindow.cpp`

### 2. Wrong Socket File Descriptor After `pi_accept()`

**Symptom:** App crashed immediately after connecting to a real Palm device.
All DLP calls (readUserInfo, openDB, readRecords) failed or segfaulted.

**Root Cause:** `ConnectionWorker::doConnect()` called `pi_accept(sock)` which
returns a *new* connected socket (`acceptResult`), but then emitted
`connectionEstablished(sock)` — the *listening* socket. Every subsequent
pilot-link DLP call used the wrong fd.

**Fix:** Changed `emit connectionEstablished(sock)` to
`emit connectionEstablished(acceptResult)`.

**File:** `src/palm/kpilotdevicelink.cpp`

### 3. Conduit Double-Delete on Shutdown

**Symptom:** Crash (pure virtual method call or segfault) when closing the
app, caused by both `SyncEngine` and `ConduitManager` trying to delete the
same conduit objects.

**Root Cause:** `SyncEngine::registerConduit()` called `setParent(this)` on
conduits, stealing ownership from `ConduitManager`. Both destructors then
tried to delete.

**Fix:** `SyncEngine` now holds non-owning pointers. It does not re-parent,
does not delete in `unregisterConduit()`, and does not delete in its
destructor. `ConduitManager` is the sole owner of plugin conduit objects.

**Files:** `src/sync/syncengine.cpp`, `src/sync/syncengine.h`

### 4. Dashboard Quick-Action Buttons Not Wired

**Symptom:** The "Connect to Device" and "Start HotSync" buttons on the
Dashboard page did nothing when clicked.

**Root Cause:** `DashboardWidget` emitted `connectRequested()` and
`hotSyncRequested()` signals, but `KF6MainWindow` never connected them
to any slots.

**Fix:** Added connections in `setupConnections()`:
- `DashboardWidget::connectRequested` → `KF6MainWindow::onConnectDevice`
- `DashboardWidget::hotSyncRequested` → `KF6MainWindow::onHotSync`

**File:** `src/kf6/kf6mainwindow.cpp`

## Architecture Status

### Conduit Plugin System — Complete

All 5 conduits have been migrated from compiled-in code to KDE plugin `.so`
files loaded at runtime via `KPluginFactory`:

| Plugin | File | Database | Status |
|--------|------|----------|--------|
| `qpilotsync_memo.so` | Memos | MemoDB | Working |
| `qpilotsync_contacts.so` | Contacts | AddressDB | Working |
| `qpilotsync_calendar.so` | Calendar | DatebookDB | Working |
| `qpilotsync_todos.so` | Todos | ToDoDB | Working |
| `qpilotsync_webcalendar.so` | Web Calendar | — | Working (skips if not due) |

Plugins are discovered by `ConduitManager` using `KPluginMetaData::findPlugins()`.
Execution order is resolved via topological sort from JSON metadata
(`X-QPilotSync-RunBefore` / `X-QPilotSync-RunAfter`).

Runtime plugin path: `QT_PLUGIN_PATH=build/lib`

### Connection Pipeline — Working

```
User clicks Connect → onConnectDevice() → Connection Dialog
  → startConnection(devicePath)
    → DeviceSession::connectDevice()
      → KPilotDeviceLink::openConnection()
        → ConnectionWorker thread: pi_socket → pi_bind → pi_listen → pi_accept
          → connectionEstablished(acceptedSocket)
            → onConnectionComplete(true)
              → readUserInfo, readSysInfo
              → openConduitAsync (advances Palm screen)
              → readyForSync signal
```

### Sync Pipeline — Working

```
User clicks HotSync → onHotSync()
  → DeviceSession::requestSync(mode, engine)
    → DeviceWorker thread: doSync()
      → SyncEngine::syncAll()
        → For each conduit in order:
          → openDatabase (DLP)
          → readAllRecords (DLP)
          → load backend records (files)
          → three-way merge
          → write changes to Palm and/or PC
          → closeDatabase (DLP)
      → dlp_EndOfSync
```

## What Remains To Be Done

### High Priority

1. **Viewer page auto-reload after sync** — The Memos, Contacts, Calendar,
   and Tasks pages don't load data from the sync folder after a HotSync.
   The data IS saved to disk but the UI doesn't refresh to show it.

2. **Second-connection freeze** — If the user connects, disconnects, and
   connects again in the same session, `startConnection()` calls
   `delete m_session` which blocks in `QThread::wait()` because the old
   worker thread may be stuck. Needs a timeout or async cleanup.

3. **Device fingerprint / user ID** — The Palm reports `userID: 0` for
   an uninitialized device. The app prompts to set a username but the
   profile still sees it as "unregistered" since the ID is 0. Needs
   better handling of fresh/uninitialized devices.

4. **ROM version display** — Logs show `ROM Version: 16.48` and
   `Palm OS: 1,040.48` which are clearly wrong bit-shift calculations.
   The version parsing in `readSysInfo()` needs fixing.

### Medium Priority

5. **Conduit settings dialog** (Plan Task 18) — No way to enable/disable
   individual conduits or configure conduit-specific settings from the UI.

6. **Plucker conduit** (Plan Task 17) — External tool conduit for offline
   web reading. Not yet implemented.

7. **Remove debug traces** — `actionmanager.cpp` and `kf6mainwindow.cpp`
   have `qDebug()` traces from this debugging session that should be
   removed or converted to proper logging levels.

8. **KXMLGUI for installed builds** — The current fix only works for dev
   builds. Need CMake install rules to place `qpilotsyncui.rc` at the
   standard KDE path (`${KDE_INSTALL_KXMLGUIDIR}/qpilotsync/`).

### Low Priority

9. **Category sync** — Categories are read from Palm AppInfo blocks but
   the log shows "Loaded 0 categories" for Memos and Todos (only Contacts
   loads 4). Category parsing may not be working for all data types.

10. **Incremental sync** — First sync works (copies Palm → PC). Subsequent
    syncs need to detect changes on both sides and merge. The three-way
    merge logic exists but hasn't been tested with real data yet.

11. **Backup/Restore** — Menu actions exist but aren't fully implemented.

12. **File installer** — Can queue files for installation but needs
    end-to-end testing with `.pdb`/`.prc` files.
